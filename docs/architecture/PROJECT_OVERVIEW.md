## 核心能力

### 模块化售卖

| 模块 | 主入口 | 技术边界 |
|------|--------|----------|
| 口播包 | `/oral-broadcast` | 数字人单人对镜口播，PPT/资料只作为脚本事实来源 |
| 讲解包 | `/explainer-video` | 文档/PPT/课程内容重导演，内容分支 + 数字人讲师分支融合 |
| TVC 包 | `/brand-tvc` | 15-20s 品牌广告创意、多镜头电影感生成与品牌收尾 |

三个包共用 `shared-core`：环境、密钥、素材、品牌、数字人、故事板、视频生成、OCR/QC、字幕/动效、交付流水线。定义文件见 `packages/`。

### 视频生成引擎

| 引擎 | 用途 | 特点 |
|------|------|------|
| Seedance 2.0 | 主力视频生成 | 音画一体、15s 上限、多参考图 |
| Kling v3 Omni | 备用/特殊场景 | 人物锚定、10s 上限 |
| Wan 2.7 | 快速预览 | 5s 上限、低成本 |
| Remotion | 本地运镜+剪辑 | 零模型成本、电影级运镜 |
| HyperFrames | 字幕/动效 | GSAP 动画、中文不乱码 |

### 23 阶段正式工作流（客户侧归纳为 4 个里程碑）

```
需求 → 剧本 → 产品板 → 人物板 → 产品使用图 → 故事板
  → 渲染方案 → 身份引用 → 精确请求确认 → 身份图生成 → 身份图验收
  → 视频生成 → 字幕合成 → 最终剪辑 → 多比例派生 → 交付
```

每一级都有 fail-closed 质量闸门，前一级未确认则后一级不会启动。

### 导演级动效设计

- **前期预演**：剧本阶段就规划好每镜的字幕文本、动效类型、安全区
- **安全区注入**：视频生成时自动避开字幕/动效区域
- **三级优先级**：预规划 > 逆向工程 > 自由文本兜底

### 讲解型双视频剪辑

- **video-use 风格编辑记忆**：`scripts/video_use_bridge.py` 为讲解型 run 写入 `project.md`、`takes_packed.md` 和 `edl.json`，让剪辑阶段围绕导演脚本、内容层级和每段视觉版式推进。
- **双分支制作**：HyperFrames/Remotion 负责文档内容动效视频，BasicRouter 数字人负责讲解视频。
- **统一融合**：`video_use_bridge.py` 统一产出融合计划；可重导演内容走分镜级视觉版式与 IntegratedExplainer，PPT 原页/截图保真时默认 `overlay/corner` 角落讲师。
- **PPT 实测最佳实践**：详见 `references/document-explainer-playbook.md`。全程保持本地零模型，`fuse.py split/overlay` 只做机械拼接或画中画。

## 技术架构

```
┌─────────────────────────────────────────────┐
│              客户交互层（Agent）              │
│   /video-auto-maker 总入口 · 引导式对话       │
├─────────────────────────────────────────────┤
│              顾问共创层（LLM）                │
│   剧本共创 · 分镜规划 · 动效设计 · 客户确认   │
├─────────────────────────────────────────────┤
│              云端渲染层（BasicRouter）        │
│   Seedance/Kling 视频生成 · gpt-image-2 图片 │
├─────────────────────────────────────────────┤
│              本地合成层（零模型）              │
│   Remotion 运镜 · HyperFrames 字幕/动画 · ffmpeg  │
├─────────────────────────────────────────────┤
│              质检交付层（fail-closed）        │
│   OCR 检测 · 媒体质检 · 成本账本 · 交付报告   │
└─────────────────────────────────────────────┘
```

## 质量保障

- **275 项源码回归**，覆盖流程绑定、审批失效、设计板预演、结构化输出、薄入口、幂等、目录形态、归档安全、模型路由身份、恢复输出隔离、Canary 晋级和交付状态；测试目录随正式包保留
- **36 个业务评测夹具**，对授权、事实、物理关系、资产身份、并发、恢复、付费生成、QC 和交付执行零容忍闸门
- **23 个权威执行阶段 / 7 条业务链**，Experience Packet V2 在客户侧归纳为 4 个易理解的制作里程碑
- **架构边界审计**：阻止内部循环依赖、跨模块写审批状态、非法阶段常量与宿主专属业务分叉；复杂函数和宽泛异常使用只允许下降、不允许静默增长
- **fail-closed 设计**：任何环节不达标则拒绝交付
- **OCR 文字检测**：自动识别画面中的意外文字
- **成本透明**：每次生成的 API 成本精确计算

## 最近更新（v4.3）

- 审批失效与客户确认证据统一由 `run_manifest.py` 管理，失效时同步清理旧展示凭证
- 展示审批物改为隔离快照 + manifest CAS 提交，保存冲突不会污染调用方内存状态
- 新增 `architecture_audit.py` 作为发布闸门，并把复杂度和宽泛异常纳入质量债务预算
- 文件 SHA-256 统一使用流式公共实现，减少跨接口产物身份漂移

- 公共业务协议与宿主薄入口分离；新增 MCP stdio、能力画像、受限 Patch 与确定性编译边界
- 根目录收敛为 Agent 发现/协议/运行必需文件，客户、交付和架构文档统一进入 `docs/`
- 正式包保留测试与业务评测，过滤 Remotion 临时 props，并强制执行目录形态合同
- 发布报告绑定源码指纹，目录与 ZIP 分别做 SHA-256、路径、链接和秘密复验

- 消除业务模块循环依赖，画布改为只读观察层，交付闸门独立为稳定合同
- 拆分故事板、分段编译、并行/串联视频生成的巨型编排函数，保留原公开接口
- 关键 JSON 状态统一使用同目录原子写入、`fsync` 与替换，降低中断后检查点损坏风险
- 修复串联视频结果中的重复 OCR 字段与失败分支不可达代码
- 交付清单、源码规模和现有回归口径与当前包保持一致

- ASR 字幕时间轴精确化（静音检测 + 云端 ASR）
- 导演级动效设计（前期预演替代后期补救）
- 字幕/动效视觉升级（spring 物理动画 + 品牌色系）
- 交叉淡化拼接（xfade + acrossfade）
- 人物服装锁定（防止跨段漂移）
- 口播音画同步强化（时长校验 + 音色连续性）
- 多比例派生（一条视频同时出 9:16/16:9/1:1）
- 安全区系统（视频生成时预留文字叠加空间）
